Les moteurs en arrière-plan

Deux pipelines, deux missions

Un pipeline, c'est une chaîne d'étapes qui s'exécute toute seule chaque matin. Personne n'a besoin de cliquer — la machine fait son travail pendant qu'on dort.

Pipeline n°1 — Actif

La mise à jour quotidienne des profils

Tourne chaque matin à 6h30, sans interruption.

Actif chaque jour

Chaque nuit, l'équipe tech de Body Pass exporte les données fraîches (porteurs, cartes, visites, établissements) et les envoie par email à une boîte dédiée. Le matin à 6h30, notre pipeline prend le relais :

Ce qu'il fait, étape par étape

À quoi ça sert concrètement

Ce pipeline permet à chaque email d'être personnalisé et à jour. Quand on parle des économies de Maria, ce sont ses vraies économies d'aujourd'hui. Quand on lui dit qu'elle est passée chez Royal Savoy hier, c'est qu'elle est vraiment passée chez Royal Savoy hier. Tous les messages s'appuient sur cette base fraîche : qui a une carte active, qui approche de l'échéance, combien chacun a économisé, quel établissement chacun a visité. C'est le socle commun à toutes les campagnes.

Sécurités en place

Si une étape ne se passe pas comme prévu, un email d'alerte arrive automatiquement chez Julieta — la machine prévient et attend qu'on vienne voir. Aucune chance qu'elle continue tête baissée si quelque chose cloche.

Pipeline n°2 — En préparation

Le moteur de campagnes personnalisées

Tourne chaque matin à 6h45, juste après le premier pipeline.

En construction

Plusieurs campagnes (Hier Notations, Utilisation J+30, Bilan mensuel) envoient un lien vers une page personnelle pour ce porteur uniquement — avec sa dernière visite, ses recommandations, ses chiffres du mois. Ce deuxième pipeline est celui qui prépare ces pages.

Ce qu'il fait, étape par étape

À quoi ça sert concrètement

Ce moteur permet de passer d'un email générique à un message qui ressemble vraiment à cette personne. Il calcule pour chaque porteur ses propres recommandations (catégorie qu'il préfère, canton qu'il fréquente, établissements pas encore essayés), fabrique une mini-page web dédiée, et donne un lien personnel à Mailchimp pour qu'il l'insère dans le bon email au bon moment.

État actuel

Le code Python qui calcule les recommandations est écrit et a déjà tourné avec succès sur les vraies données (27 porteurs traités en mode test pour Utilisation J+30, avec 100% des recommandations trouvées). L'orchestration automatique — c'est-à-dire le déclencheur du matin qui lance tout ça sans intervention humaine — est en cours de construction.

L'envers du décor numérique

Le coffre GitHub

GitHub est notre coffre-fort à codes — un endroit en ligne où l'on range, version après version, tout ce que la machine doit savoir faire.

C'est quoi GitHub, en deux phrases ?

GitHub, c'est un Google Drive pour les codes. Chaque petit programme qu'on écrit — pour calculer les économies, pour générer les pages personnelles, pour orchestrer les envois — vit dans un dossier en ligne qu'on appelle un « repo » (raccourci de « repository », c'est-à-dire « dépôt »).

L'analogie : imaginez la cuisine d'un restaurant. Chaque recette (= chaque programme) vit dans son propre classeur (= un repo). Tous les classeurs sont rangés dans une seule bibliothèque (= l'organisation bodypass-ch). Quand on améliore une recette, l'ancien classeur n'est pas jeté — il reste consultable, donc on peut toujours revenir en arrière si la nouvelle version ne marche pas.

L'autre avantage de GitHub : il offre gratuitement un hébergement web appelé « GitHub Pages ». C'est ce qui nous permet de publier les pages personnalisées des porteurs (par exemple bodypass-ch.github.io/hier-notations) sans payer de serveur.

Le voyage complet d'une donnée — du CSV au porteur

Concrètement, voici ce qui se passe entre le moment où l'équipe tech envoie les CSV par mail et le moment où Maria clique sur « Voir ma sélection » dans sa boîte de réception.

À noter : le porteur ne voit jamais « GitHub » ni « repo ». Pour lui, c'est juste une jolie page Body Pass qui s'ouvre quand il clique sur le bouton de l'email. Toute la mécanique est invisible.

Pourquoi GitHub plutôt qu'autre chose ?

Trois raisons concrètes pour Body Pass :

Gratuit pour notre usage. Tant qu'on reste sous une certaine taille (qu'on est loin d'atteindre), l'hébergement des pages personnelles ne coûte rien.

Historique complet. Chaque modification de code est enregistrée avec la date, l'auteur et le détail du changement. Si quelque chose casse demain, on peut revenir à la version d'hier en quelques clics.

Standard du marché. Si un nouveau prestataire reprend une partie du projet, il connaît GitHub. Pas de formation, pas de système maison à découvrir.
