On reconstruit le pipeline du matin pour y intégrer la gestion des étiquettes que plusieurs campagnes attendent. Sans ces étiquettes, certains envois automatiques ne savent pas qui inclure et qui exclure.

Contrainte Mailchimp

Mailchimp ne sait pas faire la récurrence mensuelle automatique

Vérifié : Mailchimp ne permet pas nativement d'enchaîner un envoi le 1er de chaque mois sans intervention humaine. Et passer à l'abonnement supérieur ne débloque pas non plus. Conclusion : la récurrence sera gérée par notre propre pipeline, pas côté Mailchimp.

Le coffre GitHub

Notre coffre-fort à codes, version après version.

C'est quoi GitHub, en deux phrases ?

GitHub, c'est un Google Drive pour les codes. Chaque petit programme qu'on écrit — pour calculer les économies, pour générer les pages personnelles, pour orchestrer les envois — vit dans un dossier en ligne qu'on appelle un « repo » (raccourci de « repository », c'est-à-dire « dépôt »).

L'analogie : imaginez la cuisine d'un restaurant. Chaque recette (= chaque programme) vit dans son propre classeur (= un repo). Tous les classeurs sont rangés dans une seule bibliothèque (= l'organisation bodypass-ch). Quand on améliore une recette, l'ancien classeur n'est pas jeté — il reste consultable, donc on peut toujours revenir en arrière si la nouvelle version ne marche pas.

L'autre avantage de GitHub : il offre gratuitement un hébergement web appelé « GitHub Pages ». C'est ce qui nous permet de publier les pages personnalisées des porteurs (par exemple bodypass-ch.github.io/hier-notations) sans payer de serveur.

Le voyage complet d'une donnée — du CSV au porteur

Concrètement, voici ce qui se passe entre le moment où l'équipe tech envoie les CSV par mail et le moment où Maria clique sur « Voir ma sélection » dans sa boîte de réception.

À noter : le porteur ne voit jamais « GitHub » ni « repo ». Pour lui, c'est juste une jolie page Body Pass qui s'ouvre quand il clique sur le bouton de l'email. Toute la mécanique est invisible.

Pourquoi GitHub plutôt qu'autre chose ?

Trois raisons concrètes pour Body Pass :

Gratuit pour notre usage. Tant qu'on reste sous une certaine taille (qu'on est loin d'atteindre), l'hébergement des pages personnelles ne coûte rien.

Historique complet. Chaque modification de code est enregistrée avec la date, l'auteur et le détail du changement. Si quelque chose casse demain, on peut revenir à la version d'hier en quelques clics.

Standard du marché. Si un nouveau prestataire reprend une partie du projet, il connaît GitHub. Pas de formation, pas de système maison à découvrir.

Carte interactive du système

Une vue d'ensemble cliquable de tout le pipeline : les sources de données, le moteur Python, les pages porteurs, la diffusion Mailchimp. Chaque bloc s'ouvre dans un panneau de détails. Pour explorer confortablement, ouvrez la carte en plein écran.
